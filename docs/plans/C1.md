## Why this is first

The process defines a standard of evidence — *a test that has never been shown to fail is
not evidence* — and **ships no harness**, deliberately. A shipped harness would be one
language's and worth nothing to the rest, and copying an upstream instrument into every
project recreates the drift that pinning exists to detect.

So the contract travels and the implementation is yours. Until `C1` is done, `H14` reports
this project as undeclared — by name, not silently.

## The five capabilities

| | Done when |
|---|---|
| **run** | one command runs every check and exits non-zero on failure |
| **count** | one command prints the number of assertions that actually **executed** |
| **floor** | a file holding a number the count may not fall below |
| **mutate** | at least one named way to break the code, paired with the test that catches it |
| **precommit** | a hook that runs the gates **after** the last edit, not before |

**Why `count` is separate from `run`.** An exit code cannot show a suite that stopped
running. A module-level `sys.exit(0)` exits clean having asserted nothing; four tests
written below a `__main__` guard never ran under one runner and did under another, and both
reported green. The count is what catches both.

**Why `precommit` says *after the last edit*.** Gates satisfied in advance and then edited
past are not gates.

## Then declare it

`docs/conventions-local.md`:

```
## Harness
- run: <command>
- count: <command printing one integer>
- floor: <path>
- mutate: <command>
- precommit: <path>
```

And name the stack in the spec — language, framework, runner, layout, ci. That is baseline:
changing it is a `D<n>`, and without it a command has nothing to point at.

## Verification

`python3 <turing-review>/scripts/check_harness.py --run <this project>` reports `ok`.

**And prove one check by breaking it before calling this done.** A hook that has never
failed is a hook nobody knows works.
